# 동료평가 때 설명하는 방법

처음에는 **"날짜 → AI 추천 → 카카오 맛집 검색 → AI 보고서 → 파일 저장"**만 기억하세요. 그다음 아래 설명을 읽고 실제 코드와 결과를 함께 열어보면 됩니다.

## 1. 먼저 이해하기: 무엇을 만들었나요?

**여행 날짜를 입력하면 국내 여행 계획을 파일로 만들어주는 파이썬 프로그램**입니다.

예를 들어 `2026-11-01`을 입력한 실제 실행에서는 다음 과정이 일어났습니다.

1. Gemini에게 여행 날짜를 보냈습니다.
2. Gemini가 **경주**를 추천하고 날씨 설명, 행사 후보, 추천 이유를 돌려줬습니다.
3. 프로그램이 추천 내용에서 **경주라는 도시 이름**을 꺼냈습니다.
4. 카카오 장소 검색에 **경주 맛집**을 요청했습니다.
5. 카카오가 돌려준 맛집 5곳의 이름·주소·분류·링크·좌표를 정리했습니다.
6. 추천 내용과 맛집 목록을 다시 Gemini에 보내 여행 보고서를 작성하게 했습니다.
7. 데이터는 JSON으로, 보고서는 Markdown으로 저장했습니다.

**핵심은 앞 서비스의 답을 다음 서비스의 입력으로 연결했다는 점**입니다. AI에게 여행 질문 한 번만 하고 끝내는 방식과 차이가 있습니다.

## 2. 약 1분 설명 대본

아래 문장을 읽고, 본인이 이해한 말로 바꿔 설명하세요.

> 날짜를 입력하면 국내 여행지를 추천하고 맛집을 찾아 여행 보고서를 만드는 프로그램입니다. 코드 구현과 점검에는 AI 도구의 도움을 받았습니다.
>
> 먼저 Gemini에 여행 날짜를 보내 도시, 일반적인 날씨, 행사 후보와 추천 이유를 JSON으로 받습니다. JSON은 도시 이름처럼 필요한 항목을 프로그램이 쉽게 꺼낼 수 있는 데이터 형식입니다.
>
> 그중 도시 이름을 카카오 장소 검색에 넣어 맛집을 최대 5곳 찾습니다. 그다음 처음 추천 내용과 맛집 목록을 다시 Gemini에 보내 최종 보고서를 만들고, 데이터와 보고서를 파일 두 개로 저장합니다.
>
> 실제 저장된 결과는 2026년 11월 1일 여행 날짜에 대한 경주 추천과 맛집 5곳입니다. 맛집 검색이 실패해도 보고서 작성을 계속하고, AI가 잘못된 JSON을 보내면 한 번만 다시 요청하도록 했습니다. API 키는 코드 밖의 비공개 설정 파일에 보관합니다.

직접 하지 않은 작업을 전부 혼자 작성했다고 설명할 필요는 없습니다. AI 도움을 받은 부분과 본인이 실제로 실행하거나 확인한 부분을 구분해서 이야기하세요. 외운 문장보다 아래 파일들을 보며 흐름을 설명할 수 있는 것이 중요합니다.

### 두 번째: 실제 보고서

[저장된 여행 보고서](results/20261015_164421_456121_2026-11-01_travel_plan.md)를 엽니다.

- 추천 지역: 경주
- 여행 날짜: 2026-11-01 (짝이 되는 JSON에서도 확인)
- 맛집: 용산회식당, 백년손님, 정록쌈밥, 남정부일기사식당, 맷돌순두부

### 세 번째: JSON에서 연결 지점

[실제 원본 데이터](results/20261015_164421_456121_2026-11-01_raw.json)를 엽니다. 전체를 읽을 필요는 없습니다.

| 찾을 항목 | 보여주는 의미 |
| --- | --- |
| `travel_date` | 입력한 여행 날짜 |

### 네 번째: 코드에서 도시 이름이 전달되는 곳

`travel_planner.py`의 `main()`에서 아래 흐름을 보여줍니다.

```python
record["recommendation"] = recommend(args.date, errors, responses)
record["restaurants"] = search_restaurants(
    record["recommendation"]["recommended_city"], errors, responses
)
```

첫 줄은 "날짜로 AI 추천을 받기", 다음 부분은 "추천 데이터에서 도시 이름을 꺼내 맛집 검색에 사용하기"입니다. 실제 코드는 한 줄 배치가 다를 수 있지만 같은 호출입니다.

### 다섯 번째: 실행 또는 자동 점검

과제 폴더에서 다음 명령을 보여줄 수 있습니다.

```bash
python3 travel_planner.py --help
python3 -m unittest discover -s tests -v
```

`--help`는 사용 방법을 보여줍니다. 자동 점검은 외부 API의 답을 시험용 응답으로 바꿔 정상/실패 상황을 확인합니다. 실제 API 실행과는 다른 점검입니다.

본인 키가 설정된 컴퓨터에서 실제 시연을 요청받으면:

```bash
python3 travel_planner.py -date "2026-11-01"
```

실시간 실행에는 인터넷·API 권한·사용량 한도가 필요합니다. 같은 날짜라도 AI 추천과 검색 결과는 달라질 수 있습니다. 키는 화면에 보여주지 않습니다. `--demo`는 가상 연습 데이터이므로 실제 API 시연이라고 설명하면 안 됩니다.

## 4. 예상 질문과 쉬운 답변

**Q. API가 뭔가요?**

내 프로그램이 다른 서비스에 일을 부탁하고 답을 받는 창구입니다. 여기서는 Gemini에 추천과 글 작성을 부탁하고, 카카오에 장소 검색을 부탁합니다.

**Q. GET과 POST는 어떻게 다른가요?**

GET은 정보를 조회하는 요청이고, POST는 처리할 내용을 보내는 요청입니다. 이 프로그램은 카카오 검색에 GET을, Gemini에 날짜와 자료를 보내는 데 POST를 사용합니다. GET에도 검색어가 전달되며, POST는 반드시 새 파일을 만든다는 뜻은 아닙니다.

**Q. JSON은 왜 쓰나요?**

AI가 긴 글만 보내면 어디가 도시 이름인지 프로그램이 꺼내기 어렵습니다. `"recommended_city": "경주"`처럼 이름과 값을 나누면 도시 이름을 바로 꺼내 다음 API에 전달할 수 있습니다.

**Q. AI가 아무 형식으로 답하면 어떻게 하나요?**

JSON 구조를 지정해서 요청하고, 받은 뒤 필수 항목과 타입을 검사합니다. 형식이 잘못됐으면 수정 지시를 넣어 한 번 더 요청합니다. 두 번째도 실패하면 오류를 저장하고 종료합니다. 무한히 재시도하지 않습니다.

**Q. 맛집 검색에 실패하면요?**

오류 목록에 기록하고, 맛집을 빈 목록으로 처리합니다. 최종 보고서에는 "데이터 없음"이라고 쓰고 나머지 여행 보고서는 계속 만듭니다. 검색 결과가 0개인 경우도 처리합니다.

**Q. AI 보고서 생성 자체가 실패하면요?**

받아둔 자료를 임시 양식에 정리해 저장하지만 `incomplete`로 표시하고 실패 코드로 끝냅니다. 이것을 완성된 AI 보고서로 제출하지 않도록 제출 ZIP에서도 제외합니다.

**Q. API 키를 왜 코드에 적지 않나요?**

GitHub에 코드를 올리면 다른 사람이 읽을 수 있기 때문입니다. 키는 `.env`에 따로 두고 프로그램이 읽습니다. `.gitignore`로 Git 추적에서 제외하고, ZIP도 필요한 파일만 골라 키 파일을 빼고 만듭니다.

**Q. AI가 맛집을 지어낸 건 아닌가요?**

맛집 목록은 카카오 장소 검색 응답에서 가져옵니다. 이름·주소·분류·링크를 보고서에 포함하도록 지시하고 해당 값이 맛집 섹션에 들어갔는지 검사합니다. 다만 AI가 추가로 쓴 모든 문장의 사실 여부까지 자동으로 검증하는 기능은 없습니다.

**Q. 날씨와 축제 일정은 정확한가요?**

날씨 API나 행사 공식 사이트를 조회하는 기능은 없습니다. AI의 계절 설명과 행사 후보이며 실제 예보나 확정 일정이 아닙니다. 과제의 중심은 JSON 출력과 여러 API의 연결입니다. 행사 후보에는 관광 활동이 섞일 수 있다는 한계도 있습니다.

**Q. 실제로 무엇을 확인했나요?**

저장된 실제 실행에서 경주 추천, 카카오 맛집 5곳, Gemini 보고서, 빈 오류 목록을 확인할 수 있습니다. 자동 점검은 날짜 오류, 키 누락, JSON 재시도, 지도 오류/0건, 보고서 실패, 키 값 제거 등을 시험합니다. 모든 상황에서 오류가 없다고 보장하는 것은 아닙니다.

**Q. 보너스 기능도 했나요?**

복수 지역 추천과 같은 날짜 결과 캐싱은 구현하지 않았습니다. 필수인 단일 도시 추천 흐름을 구현했습니다.

## 5. 함수 이름이 나오면 이렇게 이해하세요

| 함수 | 쉬운 설명 |
| --- | --- |
| `valid_date()` | 날짜 형식과 실제 존재하는 날짜인지 검사 |
| `load_env()` | 컴퓨터에 저장한 설정 읽기 |
| `request_json()` | 외부 서비스에 요청하고 JSON 응답 읽기 |
| `gemini_text()` | Gemini와 통신해서 텍스트 받기 |
| `parse_recommendation()` | 추천 데이터에 필수 항목이 제대로 있는지 검사 |
| `recommend()` | AI의 1차 여행지 추천 받기 |
| `search_restaurants()` | 추천 도시로 카카오 맛집 검색하기 |
| `make_report()` | 추천과 맛집을 AI에 보내 최종 보고서 받기 |
| `valid_report()` | 보고서 섹션·식당 정보·일정 누락 검사 |
| `finish_report()` | 주의 문구와 오류 요약 붙이기 |
| `save_results()` | JSON과 Markdown을 파일로 저장 |
| `main()` | 위 단계들을 순서대로 진행하는 진행자 |

## 6. 평가 직전 5분 연습

1. 보고서를 열어 "날짜, 추천 도시, 맛집 수"를 말해봅니다.
2. JSON에서 `recommended_city`, `restaurants`, `errors`를 직접 찾습니다.
3. "왜 AI를 두 번 부르는지" 설명합니다. 첫 번째는 도시 추천, 두 번째는 추천과 실제 장소 데이터를 합친 보고서 작성입니다.
4. "지도 실패 시 계속 진행, JSON 형식 오류 시 한 번 재요청, 키는 코드 밖"을 말해봅니다.
5. 모르는 질문에는 아는 범위를 설명하고 코드를 함께 확인합니다. 구현하지 않은 기능을 있다고 말하지 않습니다.
