# API가 뭔지, 공부한입으로 질문해 보기

## 먼저 읽을 세 문장

**API는 프로그램이 다른 프로그램의 기능이나 정보를 요청할 때 쓰는 정해진 사용 방법과 약속이에요.** 내부를 전부 만들거나 알지 못해도, 정해진 방식으로 기능을 사용할 수 있게 해 줘요.

공부한입은 질문을 우리 Python 서버에 보내고, Python 서버가 Gemini API에 설명을 요청해요. 답이 돌아오면 화면에 보여 줘요.

API 키는 AI 서비스 이용을 허용받는 비밀 값이라, 사람들이 볼 수 있는 화면 코드 대신 서버의 비밀 설정에서 읽어요.

## 이번에 실제로 넣은 질문

> API가 무엇인지 AI 초보에게 쉽게 설명해 주세요. 식당 주문에 비유하고, 공부한입에서 '질문 입력 → JavaScript fetch('/api/learn') → Python 서버 → Gemini API → 화면에 답 표시'가 어떤 뜻인지 풀어 주세요. API 키를 화면 코드에 넣지 않는 이유도 알려 주세요.

- 공개 사이트: https://gongbu-hanip.vercel.app/#learn
- 설명 수준: 완전 처음이에요
- 실행 날짜: 2026-10-15, 한국 시간
- 실행자: **사용자의 요청에 따라 Codex가 대신 입력·실행**
- 실제 표시 모델: `gemini-3.1-flash-lite`
- 실제 결과 제목: ‘API란 무엇일까요’
- 사용자 요청은 API 주제를 선택하고 시연과 GitHub 업로드를 맡기는 것이었어요. 사용자가 직접 입력하거나 내용을 이해했다고 기록하지 않았어요.

## 실제 AI 답변에서 나온 핵심

AI는 API를 프로그램끼리 데이터를 주고받는 연결 통로라고 설명하고, 손님의 주문을 주방에 전달하는 점원에 비유했어요. 직접 AI를 만들지 않고도 Gemini의 기능을 빌려 쓸 수 있고, API 키는 비공개로 관리해야 한다고 답했어요.

실제 확인 퀴즈는 **‘식당 비유에서 손님의 주문을 주방에 전달하는 API의 역할은 무엇인가요?’**였고, 답은 **‘점원’**이었어요. 정답과 해설 펼치기까지 확인했어요.

## AI 답변을 조금 더 정확하게 이해하기

‘점원’은 이해를 돕는 비유예요. 정확히는 API가 요청하는 방법, 사용할 기능, 주고받을 데이터 형식 등을 정해 줘요.

AI가 `fetch`를 AI에 질문을 전달하는 배달원이라고 간단히 표현했지만, **이 프로젝트의 브라우저는 Gemini를 바로 호출하지 않아요.** `fetch('/api/learn')`로 **우리 Python 서버**를 먼저 호출해요. 그다음 Python 서버가 Gemini API를 호출해요.

API 키가 노출되면 다른 사람이 내 서비스 이용 권한과 할당량을 사용하고 계정 조건에 따라 이용 요금이 생길 수 있어요. 은행 비밀번호처럼 바로 계좌에서 돈을 보내는 기능이라는 뜻은 아니에요.

## 우리 사이트에서 실제로 일어나는 일

| 순서 | 쉬운 말 | 담당 파일 |
| --- | --- | --- |
| 1. 질문 입력 | 사용자가 궁금한 내용을 적어요 | `index.html` |
| 2. 요청 보내기 | JavaScript의 `fetch`가 질문을 우리 서버에 보내요 | `js/app.js` |
| 3. AI에 물어보기 | Python이 비밀 설정에서 키를 읽고 Gemini에 질문해요 | `api/learn.py` |
| 4. 답 받기 | Python이 AI 답의 형식을 확인해 브라우저에 보내요 | `api/learn.py` |
| 5. 화면에 표시 | JavaScript가 설명과 퀴즈를 글자로 보여 줘요 | `js/app.js` |

질문 → 내 사이트의 Python 서버 → Gemini → Python 서버 → 내 화면

## 발표할 때 참고할 짧은 설명

아래 문장은 **실제로 읽고 이해한 뒤 본인 말로 고쳐서** 사용하면 돼요.

> 공부한입은 어려운 개념을 쉽게 설명해 주는 사이트입니다. JavaScript가 질문을 우리 Python 서버에 보내고, Python 서버가 Gemini API를 호출해 답을 받아옵니다. API 키는 화면 코드에 넣지 않고 서버 환경 변수에서 관리합니다. 저는 API가 다른 프로그램의 기능을 쓰기 위한 약속이라는 점을 설명할 수 있습니다.

마지막 문장의 이해 여부는 본인이 확인해야 해요. 대신 시연한 사실을 설명한다면 **‘API에 대해 질문하는 시연은 Codex에게 맡겼고, 결과를 읽고 구조를 공부했습니다’**처럼 실제로 한 일을 기준으로 말하면 돼요. 아직 읽지 않았다면 읽었다고 적지 않아요.

## 이제 본인이 할 최소한: 2분 확인

1. 이 문서의 첫 세 문장과 위 표를 읽어요.
2. 화면의 질문과 답이 실제로 나오는지 보고, 아래 두 질문에 혼자 답해 봐요.

**확인 1:** 화면에서 Gemini를 바로 호출하나요? → 아니요. 먼저 우리 Python 서버를 호출해요.

**확인 2:** API 키를 왜 공개 코드에 넣지 않나요? → 다른 사람이 키를 가져가 내 서비스 권한을 쓰지 못하게 하기 위해서예요.

여기까지 이해하면 학원에 사이트 주소, GitHub 폴더, 제출 ZIP을 제출하면 돼요. 추가로 직접 질문을 넣어 보고 싶다면 **‘프론트엔드와 백엔드의 차이를 식당 비유로 설명해 주세요’**를 추천해요.

참고: [MDN의 Web API 소개](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Client-side_APIs/Introduction). 일반적인 API 설명은 공식 문서와 비교했고, 공부한입의 구체적인 호출 흐름은 프로젝트 코드를 기준으로 확인했어요.
