# 공부한입 | 과제 이해부터 동료평가까지 한 번에

작성 기준: 2026-10-15 · a1-3 AI 활용 학습 과제 · AI 초보자용

> 이 문서는 과제를 이해하고 동료에게 설명하기 위한 개인 학습 자료입니다. 준비된 결과물과 본인이 실제로 한 일을 구분합니다. 아직 읽거나 이해하지 않은 내용을 이미 했다고 말하지 않습니다.

## 0. 시간이 없으면 이것부터 읽기

**무엇을 만든 거야?** 어려운 개념을 질문하면 쉬운 설명과 퀴즈를 만들어 주는 웹사이트 ‘공부한입’을 만들었습니다.

**왜 만든 거야?** AI와 프로그래밍 초보자가 어려운 용어 때문에 막히지 않도록 돕기 위해서입니다.

**어떻게 움직여?** 질문 → 내 사이트의 Python 서버 → Gemini → 내 사이트의 서버 → 화면 순서입니다.

**다 됐어?** 필수 결과물은 준비됐고 공개 사이트도 동작합니다. 본인의 이해 확인과 학원 제출은 남아 있습니다.

**평가 때 뭘 보여줘?** 실제 사이트에서 질문 → AI 답 → 퀴즈를 보여주고, 휴대폰 화면·빈 질문 안내·GitHub 설명서를 보여주면 됩니다.

## 2. 과제는 결국 무엇을 하라는 뜻이었나

**“AI가 답해 주는 나만의 웹사이트를 만들고, 다른 사람도 쓸 수 있게 인터넷에 공개한 다음, 코드·설명·기획·실행 증거를 함께 제출하라”**는 과제입니다.

코드를 AI에게 도움받아 작성해도 됩니다. 대신 화면이 어떻게 만들어졌는지, 질문과 답이 어떻게 오가는지, 오류가 나면 어디를 확인할지 본인이 설명할 수 있어야 합니다.

PDF에 적힌 40시간은 학습시간 안내입니다. 40시간짜리 영상을 제출하라는 조건은 없습니다. PDF에는 학원 제출 화면의 정확한 입력칸, 제출 마감, 별도의 동료평가 질문 목록이 나와 있지 않습니다. 아래 예상 질문은 연습용입니다.

| AI 코딩 도구 사용 증빙 | 실제 대화 발췌와 작업 요약 | 저장·업로드 |

**코드·문서·배포의 준비 완료와, 본인의 학습·학원 제출 완료는 서로 다릅니다.** 위 검증은 Codex가 수행했습니다. PDF의 ‘직접 확인’과 ‘스스로 설명’ 취지에 맞게 본인도 사이트를 한 번 열어보고 설명을 연습하면 됩니다.

데이터 저장, 다른 도구로 알림 보내기, 다크 모드, 방문자 분석은 선택 보너스입니다. 이번 필수 완료 판정에 포함하지 않았습니다. 회원가입 기능과 유료 도메인 구매도 필수가 아닙니다.

## 4. 내가 한 일과 AI가 도운 일을 어떻게 설명할까

| 구분 | 실제 진행 내용 |
| --- | --- |
| 사용자가 한 일 | 과제 PDF 제공, 초보자용 설명과 제작 요청, GitHub 업로드 요청, Vercel 로그인·연결 승인, 키 등록·배포 승인, API 학습 주제 선택과 시연 요청 |
| Codex가 대신 수행 | 요구 사항 분석, 학습 도우미 기본안 제안, 화면·서버 코드 작성, 기존 Gemini 키 연결, 배포 설정·실행, 테스트, 화면 캡처, 문서·ZIP 작성, GitHub 업로드, API 질문 대신 실행 |
| 아직 본인 확인이 필요한 일 | 사이트와 결과를 직접 읽기, 코드 흐름을 자기 말로 설명하기, 학원 제출, 동료 질문에 답하기 |

**설명 예시:**

> 저는 AI 초보 학습자를 위한 ‘공부한입’ 웹사이트를 AI 코딩 도구의 도움을 받아 제작했습니다. 코딩·테스트·문서 작업은 Codex의 도움을 받았고, 저는 과제를 제시하고 계정 연결과 배포를 승인했습니다. API를 이해하는 시연도 요청했습니다. 지금부터 실제 동작과 구조를 설명드리겠습니다.

모든 코드를 혼자 직접 작성했다고 말할 필요는 없습니다. 계정 승인만 했는데 원리까지 이해했다고 말하기보다, 이 문서로 실제 흐름을 확인하고 그만큼 설명하면 됩니다.

## 6. 어려운 용어: AI와 통신

| 용어 | 쉬운 뜻 | 공부한입에서는 |
| --- | --- | --- |
| API | 다른 프로그램의 기능을 쓰기 위한 사용 방법과 약속 | 내 서버가 Gemini의 설명 생성 기능을 사용 |
| API 연동 | 내 프로그램이 API로 다른 서비스와 연결되게 하기 | 질문을 Gemini에 보내 실제 답을 받음 |
| 요청, Request | ‘이 일을 해 주세요’라고 보내는 것 | 질문과 설명 수준을 보냄 |
| 응답, Response | 요청을 처리한 뒤 돌려주는 것 | 설명·비유·퀴즈가 돌아옴 |
| `fetch` | JavaScript에서 서버로 요청하는 기능 | `/api/learn`에 질문 전달 |
| 엔드포인트 | 특정 기능을 요청하는 서버의 주소 | `/api/learn` |
| POST | 데이터를 담아 요청하는 HTTP 방식 | 질문을 보낼 때 사용 |
| HTTP | 브라우저와 서버가 데이터를 주고받는 통신 규칙 | 요청과 응답에 사용 |
| JSON | 이름과 값을 짝지어 데이터를 담는 글 형식 | `topic`은 질문, `level`은 설명 수준 |
| Gemini | Google의 AI 모델 계열 | 쉬운 설명과 퀴즈 생성 |
| 모델 | 실제 답변을 생성하는 AI 종류 | `gemini-3.1-flash-lite` |
| 프롬프트 | AI에게 주는 질문이나 작업 지시 | 질문 내용과 쉽게 설명하라는 안내 |
| API 키 | 서비스 사용 권한을 확인하는 비밀 값 | 서버에서만 사용 |
| 환경 변수 | 코드 밖에서 읽는 설정값 | Vercel의 비밀 키 설정 |
| 로딩 | 결과를 기다리는 상태 | 버튼 잠금과 기다림 문구 |
| 타임아웃 | 너무 오래 기다려 요청을 멈추는 것 | 지연 안내와 시간 제한 |
| 쿼터 | 사용할 수 있는 양이나 횟수의 한도 | Gemini 이용 한도 |

**숫자로 나오는 응답 상태도 읽어 보기:**

| 상태 | 쉬운 뜻 | 확인할 것 |
| --- | --- | --- |
| 200 | 요청 처리 성공 | 답이 표시되는지 |
| 4xx | 요청·인증·권한·이용 제한 등과 관련된 문제 | 입력과 키 설정, 한도 |
| 400 | 요청 내용이 올바르지 않음 | 빈 질문인지 |
| 401·403 | 인증이나 접근 권한 문제 | AI 서비스 키와 권한 |
| 405 | 허용하지 않는 요청 방식 | 이 API는 질문을 POST로 전송 |
| 429 | 요청이 많거나 한도에 도달 | 이용 한도와 재시도 시점 |
| 5xx | 서버나 연결된 서비스에서 처리 실패 | 서버 로그와 외부 서비스 상태 |
| 502·504 | 연결된 서비스 오류 또는 응답 시간 초과 | Gemini 연결과 대기 시간 |

AI 회사가 반환한 오류 상태를 우리 서버가 사용자 안내용 상태로 바꿀 수도 있어요. 예를 들어 AI 회사의 키 인증 오류는 우리 화면에서 서버 설정 문제라는 안내로 보여 줍니다. 숫자만으로 원인을 단정하지 말고 안내와 로그를 함께 확인합니다.

API 자체가 AI인 것은 아닙니다. 지도·날씨·결제 등에도 API가 있고, 이번에는 AI 기능을 API로 사용합니다. 같은 프로그래밍 언어로 만든 프로그램끼리도 API를 사용할 수 있습니다.

| `requirements.txt` | Python에서 추가로 필요한 패키지를 적는 파일 | 외부 패키지가 없다고 명시 |
| 증빙 | 실제로 했다는 것을 보여주는 자료 | 스크린샷·실행 결과·AI 대화 기록 |

Serverless는 서버가 아예 없다는 뜻이 아닙니다. Vercel이 서버 실행 환경을 관리해 준다는 뜻입니다. GitHub에 코드가 있다고 Python 기능까지 자동으로 실행되는 것도 아닙니다. 실행은 Vercel이 담당합니다.

## 8. 어려운 과제 문장을 일상말로 풀면

| PDF 표현 | 실제로 하라는 일 |
| --- | --- |
| 입력 → 결과 출력까지 | 질문을 적고 버튼을 누르면 답이 실제로 나와야 함 |
| 최소 3개 이상의 페이지 또는 섹션 | 메뉴로 이동하는 공간을 3개 이상 만들기. 별도 페이지 3개일 필요는 없음 |
| 프론트와 백엔드 구조 구분 | 화면 코드와 AI 호출 서버 코드를 나누기 |
| 프론트에서 백엔드를 호출 | 화면이 서버에 질문을 보내게 하기 |
| 응답이 화면에 반영 | 서버가 준 답을 화면 글자로 보여주기 |
| 환경 변수로 API 키 관리 | 공개 코드에 비밀번호를 쓰지 않고 비밀 설정에서 읽기 |
| 오류 원인을 파악하고 수정 방향 설명 | 문제가 입력·서버·키·AI 서비스 중 어디에 있는지 확인하는 순서를 말하기 |
| 수정·재배포 | 코드를 고친 뒤 GitHub에 저장하고 새 버전이 Vercel에 올라갔는지 확인하기 |
| 배포 URL에서 재현 가능 | 동료 컴퓨터에서도 같은 주소로 열어 실제 질문해 볼 수 있어야 함 |
| 템플릿·예시 복제 금지 | 예시 서비스 이름만 바꾸는 수준을 넘어 내 목적·문구·기능 구성을 만들기 |

## 9. 공부한입의 구조를 식당으로 이해하기

| 식당 | 공부한입 |
| --- | --- |
| 손님이 주문을 적음 | 사용자가 질문 입력 |
| 주문을 전달하는 창구 | JavaScript가 우리 서버에 요청 |
| 식당의 담당자 | 우리 Python 서버가 질문을 확인하고 Gemini에 요청 |
| 요리하는 주방 | Gemini가 설명 생성 |
| 완성된 음식을 받아 전달 | Python이 답을 받고 JavaScript가 화면에 표시 |

비유는 이해를 돕기 위한 것입니다. API는 실제 사람이 아니라 정해진 기능·호출 방식·데이터 형식입니다.

**정확한 순서:**

질문 입력 → JavaScript `fetch('/api/learn')` → Vercel의 Python → Gemini API → Python → JavaScript → 화면

브라우저는 Gemini를 바로 호출하지 않습니다. 우리 서버를 먼저 거칩니다. 그래서 실제 Gemini 키를 화면에 보내지 않아도 됩니다.

## 10. 동료평가: 무엇을 어떤 순서로 보여주면 좋을까

총 4~5분 정도로 연습하면 좋습니다. 아래는 PDF에서 확인한 기능을 보여주기 위한 추천 순서이며 학원의 공식 시간 제한은 아닙니다.

| 순서 | 보여줄 것 | 말할 문장 |
| --- | --- | --- |
| 1. 소개, 약 20초 | 실제 사이트 첫 화면 | ‘AI 초보자를 위해 어려운 개념을 쉬운 설명과 퀴즈로 바꾸는 서비스입니다.’ |
| 2. 정상 질문, 약 1분 | API 질문 → 결과 → 퀴즈 정답 펼치기 | ‘이 답은 미리 적어둔 고정 답이 아니라 Gemini API가 생성한 답입니다.’ |
| 3. 메뉴, 약 20초 | 소개·AI 학습·사용 방법·도움말 이동 | ‘한 페이지 안의 네 구역을 메뉴로 이동합니다.’ |
| 4. 모바일, 약 30초 | 브라우저 폭을 줄이거나 휴대폰으로 열기 | ‘작은 화면에서는 입력과 결과를 한 칸으로 배치합니다.’ |
| 5. 오류 안내, 약 20초 | 질문을 비우고 설명 버튼 누르기 | ‘빈 질문이면 AI를 호출하지 않고 입력 안내를 보여줍니다.’ |
| 6. 결과 보관, 약 20초 | 학습 노트 다운로드 | ‘원하면 설명과 퀴즈를 TXT로 내려받을 수 있습니다.’ |
| 7. 코드와 문서, 약 1분 | GitHub 폴더·README·기획서·증빙 | ‘화면과 Python 서버 코드를 나눴고, 실행 방법과 실제 증빙도 정리했습니다.’ |

**시연할 질문:**

> API가 무엇인지 식당 주문에 비유해 쉽게 설명해 주세요. 공부한입에서 질문이 Python 서버와 Gemini를 거쳐 답이 되는 과정도 설명해 주세요.

**직접 시연할 때의 클릭 순서:**

1. 사이트에서 ‘AI 학습’ 선택.
2. 질문을 붙여 넣고 수준은 ‘완전 처음이에요’ 유지.
3. ‘쉽게 풀어 주세요’를 한 번 클릭하고 기다리기.
4. 답을 읽고 ‘정답과 해설 보기’ 선택.
5. 필요하면 ‘학습 노트 내려받기’ 선택.
6. 질문칸을 비운 뒤 다시 설명 버튼을 눌러 빈 입력 안내 보여주기.

키 설정 화면을 보여줄 필요는 없습니다. 코드의 `GEMINI_API_KEY`라는 이름은 보여줘도 되지만 실제 키 값은 보여주지 않습니다.

## 11. 평가 전에 열어 둘 자료는 세 개면 충분

1. **실제 사이트:** 평가자의 질문을 받아 바로 시연하기.
2. **GitHub README:** 서비스 소개, 배포 주소, 실행 방법, 폴더 구조 보여주기.
3. **이 노션 문서:** 원리와 예상 질문을 보고 설명하기.

추가 증거를 요청하면 기획서와 `evidence/검증기록.md`를 엽니다. 인터넷이나 AI 서비스가 일시적으로 안 되면 공개 배포 증빙과 실제 응답 파일을 보여주되, ‘지금 실시간으로 성공했다’고 말하지는 않습니다.

## 12. 30초 소개 대본

> 제가 AI 코딩 도구의 도움을 받아 만든 서비스는 ‘공부한입’입니다. AI와 프로그래밍 초보자가 모르는 개념을 질문하면 쉬운 설명, 일상 속 비유, 핵심 정리와 퀴즈를 받을 수 있습니다. 화면은 HTML·CSS·JavaScript로 만들었고, Python 서버에서 Gemini API를 호출합니다. Vercel에 공개해서 다른 사람도 주소로 접속해 사용할 수 있습니다.

## 13. 2분 설명 대본

> 저는 어려운 용어 때문에 공부가 막히는 초보자를 위한 ‘공부한입’을 AI 코딩 도구의 도움을 받아 제작했습니다.
>
> 사이트에는 소개, AI 학습, 사용 방법, 도움말의 네 구역이 있습니다. 사용자는 궁금한 내용과 설명 수준을 고르고, AI에게 쉬운 설명을 요청할 수 있습니다. 결과는 요약, 설명, 비유, 핵심 세 가지와 퀴즈로 구성됩니다.
>
> 화면의 뼈대는 HTML, 디자인과 모바일 배치는 CSS, 버튼과 결과 표시는 JavaScript가 담당합니다. 질문을 제출하면 JavaScript가 우리 Python 서버에 요청합니다. Python 서버가 Gemini API에 질문하고, 돌아온 답을 화면에 표시합니다.
>
> API 키는 서비스 이용 권한을 가진 비밀 값이라 화면 코드에 넣지 않았습니다. 서버의 환경 변수에서 읽습니다. 질문이 비었거나 AI 연결이 늦을 때는 안내를 보여주고, 요청 중에는 중복 클릭을 막습니다.
>
> Codex가 실제 AI 응답, 모바일 화면, 메뉴 이동과 다운로드를 검증했고 그 증거를 GitHub에 보관했습니다. 코드, README, 기획서, 화면과 대화 증빙도 준비했습니다. 지금 실제 사이트에서 API 질문으로 동작을 보여드리겠습니다.

연습하면서 이해한 부분은 본인 말로 바꾸면 됩니다. Codex의 검증을 본인이 직접 수행한 것으로 바꿔 말하지 않습니다.

## 14. 예상 질문과 쉬운 답변

아래는 학원의 확정 질문이 아니라 과제 학습 목표를 바탕으로 준비한 연습 질문입니다.

### 1) 무슨 서비스인가요?

‘어려운 개념을 쉬운 설명과 비유, 퀴즈로 바꿔 주는 AI 학습 도우미입니다. AI와 프로그래밍을 처음 배우는 사람이 대상입니다.’

### 2) 왜 이 주제를 골랐나요?

‘초보자는 검색한 설명에도 어려운 말이 많아 막힐 수 있습니다. 쉽게 설명받고 퀴즈로 확인할 수 있으면 도움이 된다고 생각했습니다.’

### 3) HTML·CSS·JavaScript는 뭐가 다른가요?

‘HTML은 화면 뼈대, CSS는 색과 배치, JavaScript는 클릭과 데이터 요청 같은 동작입니다.’

### 4) API가 무엇인가요?

‘다른 프로그램의 기능을 사용하기 위한 약속입니다. 이번에는 Gemini의 설명 생성 기능을 API로 사용했습니다.’

### 5) API와 AI는 같은 건가요?

‘다릅니다. AI는 답변을 만드는 기술이고 API는 그 기능을 요청해 사용하는 방법입니다. 날씨나 지도 같은 AI가 아닌 서비스에도 API가 있습니다.’

### 6) 질문하면 답이 어떻게 나오나요?

‘화면의 JavaScript가 Python 서버로 질문을 보냅니다. Python이 Gemini를 호출하고, 답이 돌아오면 화면에 표시합니다.’

### 7) fetch는 어디에 요청하나요?

‘`/api/learn`이라는 우리 서버 주소에 보냅니다. 브라우저가 Gemini에 바로 요청하는 구조는 아닙니다.’

### 8) 왜 Python 서버가 필요한가요?

‘입력을 확인하고 AI를 호출하기 위해서입니다. 비밀 키를 브라우저에 주지 않고 서버에서 사용할 수 있습니다.’

### 9) Serverless는 서버가 없다는 뜻인가요?

‘서버가 없는 것이 아니라 제가 서버 컴퓨터를 직접 관리하지 않는다는 뜻입니다. Vercel이 Python 실행 환경을 관리합니다.’

### 10) API 키는 어디에 있나요?

‘로컬 연습에서는 비공개 `.env`, 실제 배포에서는 Vercel 비밀 환경 변수에 있습니다. GitHub 코드에는 실제 키를 넣지 않았습니다.’

### 11) 키를 공개하면 왜 안 되나요?

‘다른 사람이 내 권한과 이용 한도를 사용하거나 요금이 생길 수 있기 때문입니다. 유출되면 키를 폐기·재발급하고 Git 기록에도 남았는지 확인해야 합니다.’

### 12) `.gitignore`만 있으면 모든 유출을 막나요?

‘아닙니다. Git 저장에서 제외하도록 돕는 파일입니다. 이미 저장된 비밀 값이나 수동 업로드까지 막지는 못합니다. ZIP과 화면도 별도로 확인해야 합니다.’

### 13) 로컬과 배포는 뭐가 다른가요?

‘로컬은 내 컴퓨터에서 연습하는 상태입니다. 배포는 Vercel에서 실행해 다른 사람도 접속할 수 있는 상태입니다. 키 설정도 각각 필요합니다.’

### 14) GitHub와 Vercel은 역할이 어떻게 다른가요?

‘GitHub는 코드와 변경 기록을 보관하고, Vercel은 사이트와 서버 기능을 인터넷에서 실행합니다.’

### 15) 반응형은 어떻게 했나요?

‘CSS에서 화면 폭에 따라 배치를 바꾸도록 했습니다. 큰 화면의 두 칸을 작은 화면에서는 한 칸으로 쌓습니다.’

### 16) 빈 질문이나 API 오류는 어떻게 처리하나요?

‘질문은 2~500자로 확인합니다. 빈 질문이면 입력 안내를 보여줍니다. AI 오류나 한도 초과는 다시 시도하라는 안내로 바꿔 보여줍니다.’

### 17) 답변이 너무 늦으면요?

‘12초 뒤에는 늦어지고 있다는 안내를 보여줍니다. 서버 요청과 브라우저 요청에도 시간 제한을 둬 무한히 기다리지 않게 했습니다.’

### 18) 어떤 테스트를 했나요?

‘Codex가 실제 공개 사이트의 일반 질문과 300자 긴 질문, 메뉴, 모바일, 빈 입력과 다운로드를 확인했습니다. 오류 상황을 대신 만들어 보는 자동 테스트 8개도 통과했습니다. 실제 호출과 모의 테스트를 구분해 기록했습니다.’

### 19) 실제로 문제가 있었나요? 어떻게 해결했나요?

‘초기 로컬 API 요청이 연결 오류로 실패한 적이 있고, 이후 재시도에서는 정상 응답을 받았습니다. 일시적 실패의 정확한 원인을 확정한 것은 아닙니다. 가짜 답으로 바꾸지 않고 실제 API와 공개 배포에서 다시 확인했습니다.’

### 20) AI 답이 틀릴 수도 있나요?

‘그럴 수 있습니다. 화면에서 교재와 비교하라고 안내합니다. API 학습 답변의 fetch 설명도 우리 서버를 먼저 거친다는 점을 문서에 더 정확히 풀었습니다.’

### 21) 코드가 고장 나면 어디부터 볼 건가요?

‘입력이 올바른지 보고, 서버 응답 상태를 확인합니다. 서버에서 키와 모델 설정, 인터넷과 이용 한도를 확인합니다. 필요하면 Vercel 로그를 봅니다.’

### 22) 코드를 수정하면 어떻게 공개 사이트를 바꾸나요?

‘GitHub main에 변경을 저장하면 연결된 Vercel이 다시 배포합니다. 배포 상태가 Ready인지 보고 공개 주소에서 같은 기능을 다시 확인합니다.’

### 23) 데이터는 저장하나요?

‘서비스 데이터베이스에는 저장하지 않습니다. 새로고침하면 화면 결과가 사라집니다. 필요한 결과는 TXT로 내려받을 수 있고, 질문은 답변 생성을 위해 Gemini로 전송됩니다.’

### 24) AI가 해줬는데 본인은 무엇을 했나요?

‘과제와 원하는 도움을 제시하고, 계정 연결과 키 등록·배포를 승인했으며 API 학습 시연을 요청했습니다. 코드·검증·문서 작업은 Codex의 도움을 받았습니다. 제가 이해한 범위에서 구조를 설명하겠습니다.’

### 25) 구현의 한계나 나중에 개선할 점은요?

## 16. GitHub에서 딱 네 곳만 설명하기

| 파일 | 한 문장 설명 | 평가 때 찾을 단어 |
| --- | --- | --- |
| `index.html` | 입력칸·버튼·결과 구역이 있는 화면 | `study-form`, `topic`, `answer` |
| `css/style.css` | 색과 배치, 모바일 화면을 정함 | `@media` |
| `js/app.js` | 질문 전송과 답변 표시 담당 | `fetch`, `textContent` |
| `api/learn.py` | 질문 검사, 비밀 키 읽기, Gemini 호출 담당 | `validate_input`, `generate_lesson`, `os.environ` |

`textContent`는 AI가 준 내용을 화면의 글자로 넣는 방법입니다. AI 답변을 HTML 코드로 실행하지 않도록 했다고 설명할 수 있습니다.
