# 식사비 계산기

## 대상 사용자

- 친구들과 밥을 먹은 뒤, 식사비를 똑같이 나눠 내려고 직접 계산하는 나.
- 식사한 자리에서 휴대전화로 사용한다.

## 사용 목적

- 전체 식사비와 인원수를 입력하면 한 사람이 낼 금액을 쉽게 확인한다.
- 금액이 딱 나누어떨어지지 않으면 남는 금액도 함께 확인한다.

## 화면 구성과 동작

### 화면에 보이는 내용

위에서부터 다음 순서로 배치한다.

1. 제목: 식사비 계산기
2. 전체 식사비 입력칸: 단위는 원
3. 인원수 입력칸: 단위는 명
4. 계산하기 버튼
5. 계산 결과: 한 사람당 금액과 남는 금액
6. 입력을 잘못했을 때 보여 주는 안내 문구

사진은 넣지 않고 간단하게 구성한다. 휴대전화에서 읽고 누르기 편하도록 글씨와 버튼을 크게 만든다. 구체적인 확인을 위해 본문과 입력 글씨는 18px 이상, 계산 버튼 높이는 44px 이상으로 계획한다.

### 입력과 계산 방법

- 전체 식사비는 0원 이상의 정수, 인원수는 1명 이상의 정수로 입력한다. 정수는 소수점이 없는 숫자다.
- 처음에는 입력칸을 비워 두며, 올바른 값을 입력하고 계산하기 버튼을 누르면 결과를 표시한다.
- 한 사람이 낼 금액은 전체 식사비를 인원수로 나누고 소수점 아래를 버린 값이다.
- 남는 금액은 전체 식사비에서 ‘한 사람이 낼 금액 × 인원수’를 뺀 값이다.
- 나누어떨어지면 남는 금액을 0원으로 표시한다.
- 결과는 ‘한 사람당 3,333원’, ‘남는 금액 1원’처럼 단위를 붙여 표시한다.
- 값을 바꾼 뒤 계산하기 버튼을 다시 누르면 바뀐 값으로 계산한다.

### 잘못 입력했을 때의 안내

- 하나라도 입력하지 않고 계산하기 버튼을 누르면 ‘식사비와 인원수를 입력해 주세요’라고 표시한다.
- 인원수에 0을 입력하면 ‘인원수는 1명 이상 입력해 주세요’라고 표시한다. 음수나 소수도 인원수로 허용하지 않는다.
- 식사비에 음수나 소수 등 올바르지 않은 값을 입력하면 ‘식사비는 0원 이상의 정수로 입력해 주세요’라고 표시한다.
- 입력이 잘못되었을 때는 계산 결과를 표시하지 않는다. 앞서 계산한 결과가 있다면 지워서 잘못된 입력의 결과로 오해하지 않게 한다.

## 필요한 자료

- 내가 정한 제목, 입력칸 이름, 버튼 이름, 안내 문구.
- 계산 방법: 전체 식사비를 인원수로 나누는 방법과 남는 금액을 구하는 방법.
- 계산을 확인할 예시: 30,000원과 3명, 10,000원과 3명.
- 사용자가 그때그때 입력하는 전체 식사비와 인원수.
- 외부 사진, 글, 글꼴, 라이브러리는 사용하지 않는다. 별도로 가져올 자료와 사용 허락이 필요한 자료는 없다. 글꼴은 기기의 기본 글꼴을 사용한다.

## 필수 기능

- 전체 식사비와 인원수 입력.
- 계산하기 버튼을 누르면 모두 똑같이 나눠 낼 금액 계산.
- 한 사람당 금액과 남는 금액 표시.
- 입력하지 않았거나 올바르지 않은 값을 입력했을 때 안내.
- 휴대전화에서 읽기 쉬운 큰 글씨와 누르기 쉬운 큰 버튼.

## 완료 기준

아래는 다음 미션에서 페이지를 만든 뒤 확인할 조건이다. 현재 확인을 마쳤다는 뜻은 아니다.

1. 전체 식사비에 30,000원, 인원수에 3명을 입력하고 계산하기 버튼을 누르면 ‘한 사람당 10,000원’, ‘남는 금액 0원’이 표시된다.
2. 전체 식사비에 10,000원, 인원수에 3명을 입력하고 계산하기 버튼을 누르면 ‘한 사람당 3,333원’, ‘남는 금액 1원’이 표시된다.
3. 입력칸 중 하나라도 비운 채 계산하기 버튼을 누르면 ‘식사비와 인원수를 입력해 주세요’라고 표시된다.
4. 식사비에 10,000원, 인원수에 0명을 입력하고 계산하기 버튼을 누르면 ‘인원수는 1명 이상 입력해 주세요’라고 표시되고 계산 결과는 나오지 않는다.
5. 금액이나 인원수를 바꾸고 계산하기 버튼을 다시 누르면 새로 입력한 값에 맞는 결과가 표시된다.
6. 휴대전화에서 본문과 입력 글씨는 18px 이상, 계산 버튼 높이는 44px 이상이다. 화면 너비 360px에서도 입력칸과 결과가 잘리지 않고, 가로로 화면을 밀지 않아도 볼 수 있다.
7. 다른 파일이나 회원가입, 로그인, API 키, 별도 서버 없이 HTML 파일 하나를 브라우저에서 열어 계산할 수 있다. 사진이나 외부 자료를 불러오지 않으므로 인터넷 연결 없이도 계산된다.
8. 전체 식사비에 0원, 인원수에 3명을 입력하고 계산하기 버튼을 누르면 ‘한 사람당 0원’, ‘남는 금액 0원’이 표시된다.

## 추가 기능

- 다시 입력하기 버튼: 입력한 금액과 인원수, 계산 결과와 안내 문구를 한 번에 지운다.
- 이 버튼은 나중에 추가할 기능이며 이번 제작의 필수 기능에는 포함하지 않는다.

## 한계 및 비목표

1. 모든 사람이 똑같은 금액을 내는 경우만 계산한다. 사람마다 다르게 내는 금액이나 남는 금액을 누가 낼지는 정하지 않는다.
2. 이전 계산 기록은 저장하지 않는다. 페이지를 다시 열면 금액과 인원수를 새로 입력한다.
3. 회원가입, 로그인, 회원 관리 기능은 만들지 않는다.

## 검증 방법

휴대전화 계산기의 결과와 페이지에 표시되는 금액을 비교한다.

1. 휴대전화 계산기에서 30,000 ÷ 3을 계산한다. 결과가 10,000인지 확인한다.
2. 페이지에도 30,000원과 3명을 입력하고 계산하기 버튼을 누른다. 한 사람당 금액이 휴대전화 계산기의 결과와 같은 10,000원인지 확인한다.
3. 남는 금액도 확인하기 위해 페이지에 10,000원과 3명을 입력한다. 한 사람당 3,333원, 남는 금액 1원인지 확인한다.
4. 휴대전화 계산기로 3,333 × 3 + 1을 계산한다. 처음 입력한 식사비인 10,000원과 같으면 나눠 낼 금액과 남는 금액이 맞는 것으로 판단한다.

위 절차는 페이지 제작 후 실행할 계획이며, 지금 실제 페이지의 계산을 확인한 것은 아니다.

## 기획 과정

- AI에게 쉬운 말로 한 번에 하나씩 질문하도록 요청하고, 질문에 답하며 사용자와 목적, 화면, 계산 방법, 추가 기능 등을 정했다.
- 남는 금액 표시, 빈칸과 0명 입력 안내, 휴대전화에서 쓰기 편한 화면, 기록을 저장하지 않는 방식, 로그인 없이 바로 사용하는 방식을 선택했다.

- 입력 숫자의 범위, 글씨와 버튼의 구체적인 크기 등은 답변을 바탕으로 AI가 작성 단계에서 구체화한 내용이다. 사용자는 기획서 내용과 쉬운 설명을 읽은 뒤 ‘내용은 내 생각이랑 맞아’라고 답하여 기획 의도와 일치함을 확인했다.
